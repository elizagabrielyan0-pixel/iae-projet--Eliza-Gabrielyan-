# Use case canvas — Préparation BPMN As-Is

*Synthèse sur une page · Eliza Gabrielyan · 6 oct. 2026*

| **PROBLÈME** | **UTILISATEURS** | **VALEUR** |
|---|---|---|
| Environ une semaine par BPMN « as-is », en partant d'une page blanche à partir des sources de l'atelier client. | Consultante SAP (owner, usage individuel), qui relit tout en fin d'exécution (pas de validation intermédiaire). | Partir d'un premier jet (tableau, questions, BPMN) à orienter et corriger, et se repérer plus vite dans le processus du client. |
| **PROCESSUS ET ACTEURS** | **DONNÉES** | **IRRITANTS** |
| Charger les conventions → Consolider les sources → Reconstruire le processus → Contrôler les zones floues → Assembler le livrable → Générer le `.bpmn`. | Notes d'atelier Word, PDF du client, transcription Teams / e-mails ; fiche de conventions, 2 modèles BPMN de référence, norme BPMN 2.0. | Reconstruire l'ordre, les acteurs et les exceptions depuis les notes, repérer les manques, tout dessiner ; conventions KPMG appliquées sans être écrites. |
| **RÈGLES** | **RISQUES** | **INDICATEURS DE RÉUSSITE** |
| Pratique réelle > procédure écrite (écart signalé) ; source et statut sur chaque élément ; décrire l'existant, sans le « to-be » ; aucune validation intermédiaire. | Données client confidentielles (outils KPMG autorisés seulement, noms anonymisés) ; consigne cachée dans un document client ; PDF scannés mal lisibles. | Passer de 5 à 3 jours ouvrés entre l'atelier et un BPMN prêt à envoyer ; décisions avec conditions explicites et rien d'inventé (critères *must*). |

*Chaque case se retrouve, en détail, dans requirements.md.*
