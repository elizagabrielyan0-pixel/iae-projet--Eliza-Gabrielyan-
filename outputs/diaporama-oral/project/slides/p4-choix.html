Points à dire : - Skill plutôt qu'agent : un agent choisit lui-même son chemin et peut tourner sans surveillance. Ici les 6 étapes sont toujours les mêmes : un agent n'apporterait rien et ajouterait du risque. - Aucun connecteur (MCP) ni API : le workflow n'a rien à aller chercher ailleurs, et surtout il ne doit rien envoyer. Moins d'accès = moins de risque sur des données confidentielles. - Pas de validation au milieu : comme rien ne peut sortir sans moi, une relecture finale suffit. - Hors périmètre : le processus cible (to-be) et la configuration SAP. Le workflow décrit l'existant, c'est tout. - Reporté à plus tard : reprendre les corrections que je fais dans Camunda quand je relance le workflow.
